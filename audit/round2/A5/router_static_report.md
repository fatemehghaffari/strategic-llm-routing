# Static benchmark router baseline (router_static): DONE

29 Sep 2026. Branch aamas2027-revision, not committed.

## What it models

A deployed offline router (RouteLLM or Not Diamond style, or a gateway such as
OpenRouter that trusts the model name). Every query of task type x goes to the
provider with the best published offline capability for x, which is the benchmark
table `inst.M[x, i]` (5-shot RouterBench capability, the same table the oracle uses).
It never looks at observed outcomes and pays nothing. Ties within 1e-12 are broken
by a seed-fixed random priority over providers (`default_rng([seed, 4242])`). With
several query rows per context label, it uses their unweighted mean capability.
For q7 and merged5, `key = arange(Q)`, so this reduces to argmax_i M[x, i].
Outcomes are drawn from the same uniform stream as `run_router` (`seed + 7919`), so
the comparisons use common random numbers.

## Implementation (additive only)

- `audit/round2/A4/scripts/mechanisms.py`: new functions `static_benchmark_choice` and
  `run_router_static`, placed just before `run_router_audit`. `run_router(rule="static")`
  dispatches to `run_router_static` in a new first statement. The other agent's
  uncommitted edits (`reward_fn`, `run_router_audit`, `run_second_best` kwargs) are kept.
  The result dict also returns `static_choice` and `static_bench`.
- `run_v3.py`: `ROUTERS_V2` holds the original three routers, and
  `ROUTERS = {**ROUTERS_V2, "router_static": "static"}`, so `PROFILES["router_static"]` is
  exploit_slow, exploit_fast, average and learning. `V2_BASE` is now built from
  `ROUTERS_V2`, so the three v2 routers still go through `baselines_v2.one_run` and
  router_static does not. `one_run_new` has a new `router_static` branch that uses
  `BL2.Average`, `BL2.ExploitDecay` or `Learner`, and writes `static_choice` and the
  exploit constants into the trace meta.
- `make_tasks_v3.py`: new `static` task list (80 tasks). The i1 bridge covers merged5
  {iid, real} x {3e5, 3e6} x 20 seeds with profiles exploit_slow, exploit_fast and
  average. The i2 learning runs are at 3e6 with 10 seeds: q7 {iid, bursty} and merged5
  {iid, real}. The main and real lists are regenerated byte-identical.
- `aggregate_v3.py`: an optional second argument sets the output path. The default is
  unchanged.

## Sanity checks (merged5, n = 1e5, seed 0, every v2 subset)

For each subset I ran the static router against four provider strategies. `Full` is a
test-only strategy where every provider delivers M, but the honest provider is still
held at its floor mu. `avg` is the midpoint strategy, shown next to its analytic value
(honest pick delivers mu, strategic pick delivers (M+mu)/2). exploit_slow and
exploit_fast are the decaying strategies. The router's choice equals argmax M on every
type in every subset (asserted). With a Full provider, revenue equals `oracle_per_round`
exactly, and `avg` matches its analytic value to 4 decimals.

## Reading

- The static router is the most exploitable baseline. Under shading, revenue per round
  is 0.22 (exploit_slow) and 0.11 (exploit_fast) on iid, which is 0.30 and 0.15 of the
  oracle. That is below greedy (0.34 and 0.26), and the learning routers UCB and eps sit
  near 0.50, the honest floor, because they move traffic to the honest provider. The
  static router never moves traffic. In the subsets where GPT-4 is benchmark-best
  everywhere (k3_q50, k4_q90, k5_q50), exploit_fast gives it about 0.01.
- Its numbers do not depend on the horizon. ExploitDecay's decay length D = n/K grows
  with n, so the shaded fraction of rounds is the same at both horizons. That follows
  from how the profile is defined; it is not a bug.
- Under `average`, the static router is at 0.621, the same as UCB and eps and above
  greedy. It routes on true capability, and the midpoint shading keeps the ranking.
  PL-MESP S* beats every router-profile cell at both horizons and in both orders, on
  the mean over subsets.

## Caveats (possible problems)

1. In every q10 subset and in k3_q90, the honest provider Mixtral is benchmark-best on
   knowledge_qa, which is 45% of the mass. By the v2 convention an honest provider
   delivers only its floor mu = min(M, M_Mistral-7B), so the static router sends 45% of
   its traffic to a provider running well below its benchmark. That caps
   static/average there at about 0.577, below its oracle of 0.72. The same convention
   applies to every rule, but the static router shows it most.
2. static/average is 0.663 in the all-GPT-4 subsets, while PL-MESP S* ranges from 0.63
   to 0.72 across subsets and orders. S* comes out below static/average in k3_q50 (both
   orders), in k4_q90 and k6_q50 on the real order, and in k4_q90 iid at 3e5 (0.660).
   `average` is not a best response to the static router, whereas S* is an equilibrium
   for PL-MESP. Compare S* against the exploit or learning rows, not against `average`.
3. In the real order, k4_q10 exploit_fast gives 0.40, against 0.25 for iid. The
   WildChat window is heavier on the types where the honest Mixtral is picked. This
   comes from the stream, not the code.
